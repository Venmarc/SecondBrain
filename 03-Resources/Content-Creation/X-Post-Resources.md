# X Post Resources

> **One-line summary:** Turn real build decisions, saved ideas, and strong replies into specific X posts without inventing new work.

## The rule

A post needs a real source.

The source can be:

- A shipped Codon Labs decision.
- A screenshot or recording that proves the decision.
- A handwritten reply that contains a useful observation.
- A saved idea that has become a testable design question.
- A source-backed lesson from a complete bookmark read.

Do not start a feature only to create content.

## What the complete reads support

The current full reads support these patterns. They do not prove a universal growth formula.

### 1. Explain the reason behind the artifact

A checklist can be useful because it is saveable. It becomes more useful when the reader understands the reasoning behind each step.

The complete source about a 180-day AI agency checklist says that the checklist only works when the reader understands the context, numbers, reasoning, and connection between phases.

**Use it for Codon Labs:** Do not post only a screenshot of the footer or process page. Explain the visitor problem and the design tradeoff.

**Post prompt:**

> The screenshot is the easy part. The decision behind it was `[decision]`.
>
> I changed it because `[visitor problem]`.
>
> Without that context, the page looks polished but the choice is invisible.

Source: [Luke Pierce checklist post](https://x.com/lukepierceops/status/2101468405601563091). Stored source: `source-3a552525caefb6c65733`.

### 2. Make the demo prove one thing

The complete HyperFrames source describes using demo videos for projects, finding an inspiration, giving it to an agent, revising the script and copy, and rendering in a cloud environment when local hardware becomes a barrier.

The useful lesson is not “make a video.” It is “choose one thing the video must prove.”

**Use it for Codon Labs:** Make short videos about one page function or design decision:

- How the footer acts as an index.
- How the process trace guides the scroll.
- How a fake company becomes coherent through copy and links.
- How a page changes between the first and final version.

Do not make a generic “here is my website” tour.

**Post prompt:**

> I made a short video to show `[one behaviour]` on Codon Labs.
>
> It is not a full site tour. I wanted to prove `[specific claim]`.
>
> The part that changed the result was `[decision]`.

Source: [Zan's HyperFrames article](https://x.com/zanbuilds/status/2097675410821574761). Stored source: `source-925dd508b8800394cf05`.

### 3. Turn one project into many angles

The complete content-ideas source lists question and comparison angles such as:

- History, rise, fall, future, psychology, science, business, evolution.
- Biggest mistake, success, failure, hidden side, untold story.
- What everyone gets wrong, what nobody noticed, how it works, why it works.
- Before and after, then and now, old and new, best and worst.
- Myth versus reality, expectation versus reality, theory versus evidence.
- One decision, one mistake, one person, or one event that changed everything.

This is a prompt bank, not a license to make empty listicles.

**Use it for Codon Labs:** Apply the angles to decisions that already exist:

- The complete timeline of the footer.
- The one decision that changed the process page.
- What visitors get wrong about a fictional service site.
- Before and after: decorative footer versus useful index.
- Expectation versus reality: a cloning website versus a believable service world.
- The hidden side of a portfolio build: the cuts required to finish it.

Source: [50 content ideas post](https://x.com/successfaceless/status/2103291142309880222). Stored source: `source-fcddd24ddffad549e3f3`.

### 4. Show the prompt beside the result

The complete motion-gallery source describes a gallery where each motion graphic appears beside the prompt or skill that made it.

**Use it for Codon Labs:** Show the result beside the decision or constraint that shaped it. This does not require publishing private prompts. A short public design constraint is enough.

Examples:

- Result: footer index.
- Constraint: the footer must explain what the company is and where the visitor can go next.

- Result: process trace.
- Constraint: motion must help the visitor locate the current step.

- Result: fictional-company copy.
- Constraint: the site must feel in-world without claiming the service exists.

Source: [p4n motion gallery post](https://x.com/p4nthera_/status/2107175720086589633). Stored source: `source-b92daa43a59a1b91519f`.

### 5. Show the analysis before the output

The complete logo-grid thread is useful because the prompt does not ask an agent to make a pretty construction grid. It asks the agent to inspect the actual vector geometry first, measure it, preserve intentional imperfections, and remove guides that do not earn their place.

**Use it for Codon Labs and your own posts:** Show the design analysis before the visual result. The post can explain what the agent measured, what it refused to invent, and what changed after visual inspection.

**Post prompt:**

> I stopped asking the agent to make the logo grid look precise. I asked it to measure the actual mark first.
>
> That difference matters. A generic grid can look technical while explaining nothing about the logo.
>
> The useful output came from the constraints: measure the geometry, preserve the imperfect parts, and remove every guide that does not earn its place.

Source: [aecyydesign logo-grid thread](https://x.com/aecyydesign/status/2106808569891004820). Stored source: `source-f761bab9c1dc1381bffa`.

### 6. Make the destination part of the prompt

The complete Image2 poster thread treats the destination as part of the design brief. It specifies a vertical poster, a readable headline, a controlled palette, meaningful copy, realistic material behaviour, and a clear interaction between the subject and the type.

The complete image-prompt thread makes the same move for social images and slides. It specifies the empty space for text, the aspect ratio, the exact words, the elements that must remain unchanged, and the final cleanup pass.

**Use it for posts:** When explaining an agent result, show the destination constraint that made the result useful.

**Codon Labs examples:**

- A footer must work as the last page section and as a directory.
- A process video must remain readable without sound.
- A mobile hero must keep the headline, image, and facts in view.
- A screenshot must show a real interaction, not only a decorative frame.

Sources: [Mr Larus poster thread](https://x.com/MrLarus/status/2096583023277822359) and [Osabori image-prompt thread](https://x.com/osabori_code/status/2106313054543872038). Stored sources: `source-d4ab36c560bdafd75986` and `source-dba04ab7f4a34ba7e9e9`.

### 7. Use exact avoid rules

The saved card for the Claude Opus design guide says that generic instructions to avoid a generic look can replace one default style with another. It recommends naming the exact things to avoid.

This source is still partial. Treat it as a routing signal, not a complete article claim.

**Use it for Codon Labs:** Write the avoid list before asking an agent for a design change:

- Do not add another soft gradient.
- Do not turn every section into a rounded card.
- Do not make the footer a second hero.
- Do not use motion that hides the reading order.
- Do not add a feature only because it looks good in a demo.

This connects directly to the handwritten idea note [[00-Inbox/Idiom Idea]].

## Codon Labs post inventory

These ideas already exist in your notes. They are post material when you make or test them. They are not reasons to expand Codon Labs tonight.

### Design constraints for agents

Source: [[00-Inbox/Idiom Idea]].

**Post angle:** Agents follow generic design instructions, but numbers and explicit exclusions reduce ambiguity.

**Draft seed:**

> “Make it white with a little blue” is a feeling. “Use 90% white and 10% blue” gives the agent a measurable direction. I’m starting to write the things I don’t want my agents to do, not only the things I want them to make.

Use your actual test before publishing this.

### VGPU and light interaction

Source: [[00-Inbox/Idiom Idea]].

**Post angle:** A visual effect becomes more useful when it carries state or orientation.

**Questions to test:**

- Can the cursor reveal the chart state?
- Can light show movement through a page?
- Does the effect explain anything, or only decorate the page?

### ASCII as a visual system

Source: [[00-Inbox/Idiom Idea]].

**Post angle:** ASCII is not only retro styling. It can turn an image or identity into a visible grid of characters.

**Codon-adjacent use:** Keep this as a portfolio or experiment post. Do not force it into Codon Labs unless the page needs it.

### Low-quality, high-detail imagery

Source: [[00-Inbox/Idiom Idea]].

**Post angle:** A detailed image can feel low quality on purpose if the pixel structure becomes part of the visual language.

**Useful post shape:** Show the reference, the compression or pixel test, and the point where the image stopped reading clearly.

### Astro for the content surface, Next.js for the app surface

Source: [[00-Inbox/Idiom Idea]].

**Post angle:** Framework choice can follow visitor needs. Astro can serve a content-heavy public surface while a separate app handles authenticated product work.

Do not present this as a universal framework rule. Present the boundary you chose and the reason.

### Components instead of screenshots

Source: [[00-Inbox/Idiom Idea]].

**Post angle:** A site can show a product by rebuilding a small inactive component instead of embedding a flat screenshot.

**Post prompt:**

> The best product screenshot I saw was not a screenshot. It was a small inactive copy of the product built from HTML, text, borders, and icons. You can zoom in, and it still feels like a real interface.

Name the site and verify the implementation before claiming how it was built.

### Image search and editing workflow

Source: [[00-Inbox/Idiom Idea]].

**Post angle:** An agent workflow can source an image, inspect it, and edit it against a requirement list.

**Proof needed:** Show the requirement list, source, edit, and result. The workflow is stronger than a tool list.

### Idea capture itself

Source: [[00-Inbox/Idiom Idea]].

**Post angle:** The useful system is not “have more ideas.” It is “do not lose the idea before it becomes a note.”

This is a personal systems post. Keep it separate from Codon build notes.

## Post families to use next

### Codon Build Notes

Use when a real site decision ships.

- Footer as index.
- Process trace as orientation.
- Page links as world-building.
- Fiction disclosure as a trust boundary.

### Details People Skip

Use when one small decision changes the visitor's understanding.

- Footer labels.
- Mobile order.
- Link destinations.
- Motion timing.
- Text hierarchy.

### Agent Design Constraints

Use when an agent produces a generic result and you improve the instruction.

- State ratios.
- Name exclusions.
- Give a reason.
- Give a rejected alternative.
- Show the reference and the desired difference.

### Build Restraint

Use when you cut work.

- A new feature deferred.
- A footer idea rejected.
- A portfolio project not started.
- A visual effect removed because it did not explain anything.

### Reply to original

Use when a reply contains a full observation.

- Start with the reply's claim.
- Add the Codon Labs or personal example.
- Remove the original post's dependency.
- Publish the complete thought from your own account.

## Working rule

Before drafting, choose:

1. The real source.
2. The post family.
3. The one claim.
4. The proof.
5. The next action or question.

If one of these is missing, the idea is not ready to publish.
